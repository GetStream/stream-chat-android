# OpenUI

`stream-chat-android-ai-openui` brings [OpenUI](https://github.com/thesysdev/openui) to Stream's AI components: OpenUI Lang is the compact, streaming-friendly language models answer in to describe generative UI. The module plugs into the generative UI layer of `stream-chat-android-ai-compose`.

The language runtime (package `io.getstream.chat.android.ai.openui.lang`) is ported from upstream's TypeScript `@openuidev/lang-core` 1.0 and follows the OpenUI Lang 1.0 specification. It's tested against upstream with conformance fixtures generated by that implementation.

## Parse a response

```kotlin
val parser = createParser(schema = OpenUIJson.parse(schemaJson), rootName = "Card") // upstream `library.toJSONSchema()`
val result = parser.parse(responseText)
result.root        // the root ElementNode, or null
result.meta.errors // validation errors, readable by a model
```

`createParser` takes a library's JSON Schema; its `functions` and `actions` join the built-in `@` calls.

The entry statement is `root`. Without one, the first statement that calls the library's root component renders, with a `no-root` warning (`ValidationError.isWarning`); with neither, nothing renders and `no-root` is an error. A root that picks a component at runtime, such as `root = $dark ? a : b`, is resolved when the response is evaluated.

While a response streams, keep one `createStreamingParser(schema, rootName)` and pass it the full text so far with `set(text)`; it only re-parses the statement that is still growing. Pass `complete = true` once the stream has ended: until then, a `$name` at the very end of the text may still be growing and isn't declared. `mergeStatements(existing, patch)` applies an edit-mode answer (only the statements that changed) to a previous program.

Values follow JavaScript semantics, because the reference implementation is TypeScript: `OpenUIValue` is JSON plus elements and expressions, `undefined` is a Kotlin `null`, and conversions (number formatting, `Number()`, truthiness) follow JavaScript's. Model output can't crash the parser: nesting or chains deeper than any real program, and references that would expand past any real program's size, read as `null`, and non-finite numbers serialize as `null`.
