AIConversationState

class AIConversationState<M : AIMessage>(transport: AIConversationTransport<M>, scope: CoroutineScope, val approver: AIToolApprover? = null, replyTimeout: Duration? = DefaultReplyTimeout)

The state behind a conversation with an AI agent, and what the person does in it.

It holds the conversation's messages, where the latest exchange with the agent is and why it failed, and it sends what the person asks through its AIConversationTransport. Give it to AIConversation(state) and ChatComposer(state), which show it and act on it:

class ChatViewModel(transport: AgentTransport) : ViewModel() {
    val conversation = AIConversationState(transport, viewModelScope)
}

Column {
    AIConversation(
        state = viewModel.conversation,
        modifier = Modifier.weight(1f),
        footer = {
            if (status == AIConversationStatus.Error) {
                Button(onClick = viewModel.conversation::retry) { Text("Try again") }
            }
        },
    )
    ChatComposer(state = viewModel.conversation)
}

What the person sends shows straight away as pendingMessage, and the agent thinks until its reply starts. Requests and stops are numbered, so the outcome of one that a newer one replaced is ignored. After a stop, the reply counts as finished even while the transport still marks it as generating, and one that showed nothing is left out of messages.

It is confined to the thread of scope: pass one that runs on the main thread, such as a viewModelScope, and call it and its feed there. It lives as long as scope.

Parameters

transport

How the state reaches the agent and learns what the conversation holds. The state connects to it straight away.

scope

Where requests, stops and the reply timeout run.

approver

Who answers tool calls' questions and sign-ins on this device, which the conversation asks them.

replyTimeout

How long the state waits, once the agent has a request, for the agent to start its reply or say what it is doing, before it shows an AIAgentError. While the agent says it is working, such as thinking, it waits as long as that takes. Null or Duration.INFINITE waits as long as it takes.

retry
Link copied to clipboard
fun retry()

Tries again after error. When the transport couldn't send the person's message, it sends it again, with the same message id. Otherwise nothing is sent: the agent had the request but couldn't answer it, stopped partway through its reply, or didn't answer in time, or older messages couldn't load. Sending the message again would add it twice, so retrying forgets the error, as clearError does, and the person asks again. Does nothing without an error.
